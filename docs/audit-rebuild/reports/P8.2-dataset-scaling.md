# P8.2 Dataset Scaling

Captured: 2026-07-12 PDT

State: `EVIDENCE_READY`

Evidence ID: `EV-P8-SCALE-002`.

| Dataset/state | Observation |
|---|---|
| empty/typical Home | bounded summary DOM and similar local paint |
| 500-trade Home | remains bounded because only aggregates render |
| 500-trade History | 8,185 live elements, all 500 cards, 39,961 px scroll, 5,049-line accessibility snapshot |
| 500-trade serialized fixture | 335,966 bytes before realistic long notes/media metadata |
| Worker request | entire dataset JSON every PUT, rejected above 1 MiB |

History, filtering, sorting, export, localStorage serialization, merge signatures,
and cloud PUT are O(n) full-dataset operations. Analytics repeatedly traverse the
same arrays and several charts materialize all points. At the fixture's average
serialized density, the Worker cap is reached around the low thousands of records;
real notes/tags raise the bytes per trade and lower that boundary.

The current product fails the no-unbounded-DOM-growth budget. Target tests must cover
0, 1, 100, 500, 5,000, and 50,000 records with bounded visible DOM, incremental
storage/sync commands, indexed search, paginated export, and workerized heavy
analytics where measurement proves necessary.
