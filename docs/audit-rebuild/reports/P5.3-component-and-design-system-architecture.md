# P5.3 Component and Design-System Architecture

Captured: 2026-07-12 PDT

State: `EVIDENCE_READY`

Evidence ID: `EV-P5-ARCH-003`.

## Current State

Tailwind utilities, inline styles, embedded CSS/keyframes, chart literals, and a
small theme block jointly define the interface. There is no enforceable spacing,
type, radius, elevation, target-size, state-color, or motion contract. Similar cards,
buttons, controls, and status messages are independently authored.

## Proposed Layers

1. **Foundations:** semantic color, type roles, 4/8 px spacing, radii, elevation,
   safe-area, z-index, and motion tokens.
2. **Primitives:** audited interactive controls with complete states and accessible
   names/descriptions.
3. **Patterns:** record card, status receipt, drawdown warning, metric pair, chart
   frame, progress segment, bottom sheet, destructive confirmation.
4. **Compositions:** Today, Capture, Journal, Insights, and System sections.
5. **Monument:** isolated visual package receiving a pure progress view model.

No business rule may be encoded by color class selection inside a view. Components
receive semantic states such as `verified-positive`, `planned-exposure`, `pending`,
or `failed`. Storybook is optional; a lightweight in-app component harness with all
states is required for deterministic screenshots and accessibility checks.
