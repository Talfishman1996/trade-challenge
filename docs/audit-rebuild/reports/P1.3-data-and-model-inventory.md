## Dataset Schema

Top-level schema version: `2`.

```text
Dataset
  version, schemaVersion
  initialEquity
  trades[]
  tombstones[]
  clientId
  _lastModified                 frontend dataset timestamp
  lastModified                  Worker-normalized timestamp in cloud payload

Trade
  uid                           globally generated identity
  id                            locally assigned display/mutation identity
  createdAt, updatedAt, deletedAt
  date, openDate, entryTime, exitTime
  pnl, equityBefore, equityAfter
  riskPct, riskDol, phase
  direction, ticker, strategy, contracts, entryPrice, exitPrice
  setupTags[], emotionTags[], mistakes[]
  mae, mfe, images[], notes

Tombstone
  uid, deletedAt, updatedAt
```

`uid` drives merge conflict identity, but the UI and edit/delete methods use `id`.
Each device assigns `id` as its local maximum plus one. The merge does not renumber
or reject duplicate IDs.

## State and Persistence Map

| State | Owner | Persistence | Cloud synced |
|---|---|---|---|
| trades, tombstones, initial equity, derived risk fields | `useTrades` | localStorage `risk-engine-data` | yes, one KV blob |
| client identity | `tradeData.js` | localStorage `tradevault-client-id` | copied into dataset but not used for conflict rules |
| model/display/risk-control settings | `useSettings` | localStorage `risk-engine-settings` | no |
| sync ID and last-sync timestamp | `sync.js` | localStorage `tradevault-sync` | no |
| sync activity, last 12 entries | `syncActivity.js` | localStorage `tradevault-sync-activity` | no |
| chart image blobs | `imageDB.js` | IndexedDB `tradevault-images/images` | no |
| image keys | each trade record | localStorage and cloud dataset | yes |
| navigation, overlays, draft create form, undo stack | components/hooks | memory only | no |

The result is a split record: image references sync, but their blobs do not. A trade
opened on another device can contain image keys that its IndexedDB has never seen.

## Mutation and Sync Lifecycle

```text
create/edit/delete/clear/import/set initial equity
  -> normalize dataset
  -> recalculate entire chronological equity/risk chain
  -> stamp _lastModified
  -> write localStorage
  -> update React state
  -> fire-and-forget cloud PUT
  -> App mutation handler immediately starts pull/merge sync

boot / 30-second foreground interval / 15-second entry interval / focus / manual
  -> cloud GET
  -> normalize local and remote independently
  -> latest updatedAt wins per uid
  -> tombstone wins when deletedAt >= trade updatedAt
  -> latest dataset timestamp supplies dataset-level fields
  -> persist merged local result or PUT local result
```

The Worker repeats, but does not share, frontend normalization and merge code. It
accepts GET/PUT/POST without authentication, reflects any requesting Origin, and
stores the primary dataset under the fixed key `tradevault-main`.

Undo/redo bypasses `persist`. Undo removes the last trade without creating a
tombstone; a later merge can therefore restore the cloud copy. Redo restores the
saved object without a new identity or timestamp.

## Active Mathematical Model

The active gross model is fixed at 1:1 RR:

```text
E0 = 87,500
K0 = 0.33

r(E) = 1                                      for E <= 20,000
r(E) = 1 - 0.5 * (E - 20,000) / 30,000      for 20,000 < E <= 50,000
r(E) = 0.5 - (0.5 - K0)*(E-50,000)/37,500   for 50,000 < E <= 87,500
r(E) = K0 * (E0 / E)^(2/3)                   for E > 87,500

dollar risk = E * r(E)
gross win   = +dollar risk
gross loss  = -dollar risk
```

Constants, labels, milestones, slider bounds, and simulations remain centered on
the old `$20K -> $10M` challenge. Settings default to 60% win rate and `$20K`
starting equity.

## Model Consumers

- live next-trade sizing and phase
- every trade's `riskPct`, `riskDol`, `equityBefore`, and `equityAfter`
- R-multiple display, averages, distributions, MAE/MFE and duration analytics
- Home risk explorer, risk severity, summit progress, and copy
- milestone celebration and roadmap
- fixed/alternate/decay Monte Carlo trajectories and terminal wealth
- drawdown, recovery, loss-to-wipe, and survival calculations
- probability cone and expected milestone trade counts
- JSON/CSV export and settings/about copy

All simulations use binary win/loss Bernoulli outcomes. They do not model
break-even trades, fees, slippage, funding, variable execution, trade frequency, or
calendar months. P7 must decide the intended semantics before comparing outputs.

## Integrity Conditions Observed

1. `recalcTradeChain` overwrites historical `riskPct`, `riskDol`, and `phase` on
   every load or mutation using the currently imported formula.
2. Statistics classify `pnl === 0` as a loss, while Trade History colors and labels
   it as a win.
3. Settings and image blobs are outside the cloud contract despite an app promise
   of one seamless shared vault.
4. Local numeric IDs can collide after offline/concurrent additions; mutation and
   React rendering still use those IDs instead of `uid`.
5. One user mutation can launch a fire-and-forget PUT and an immediate GET/merge,
   producing duplicate requests and a race between them.
6. Undo provides no cloud deletion evidence and can be reversed by synchronization.
7. Client and Worker schema/merge implementations can drift because they are copied,
   not shared or contract-tested.

These conditions are registered as open findings. P1 records their existence; P6
and P7 own adversarial reproduction, target contracts, and closure criteria.

## Verification Result

Every persisted state family, schema field, sync trigger, mutation path, Worker
operation, active formula, and model consumer has an inventory entry. No cloud call
was made to prove behavior; P6 will use isolated fixtures and failure injection.
