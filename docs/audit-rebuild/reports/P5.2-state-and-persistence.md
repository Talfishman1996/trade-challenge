# P5.2 State and Persistence

Captured: 2026-07-12 PDT

State: `EVIDENCE_READY`

Evidence ID: `EV-P5-STATE-002`.

## Current Ownership Defects

- Initial equity exists in Settings localStorage and the synced trade dataset.
  Settings edits both, but cloud merge/import can update only the trade dataset.
- Settings' input mirror initializes once and has no reconciliation effect when the
  authoritative dataset changes.
- Navigation, nested tabs, filters, drafts, and undo history are component memory.
- Screenshot keys are records; binaries live in a separate local IndexedDB.
- Sync transport status, last timestamp, activity history, and actual record state
  are separate local sources without one state machine.
- Write/storage exceptions are commonly swallowed, so React state can advance after
  durability failed.

This opens `F-FE-HIGH-004`: initial equity can diverge between the risk ledger and
simulation settings even on one device, separate from the existing cross-device
settings omission.

## Target State Classes

| Class | Owner | Durability |
|---|---|---|
| immutable execution record | domain ledger | local DB + acknowledged remote |
| model definition/version | domain model registry | synced, migration-controlled |
| pending mutation/outbox | sync engine | durable local until acknowledged |
| UI route/filter/sheet | router/feature | URL/session as appropriate |
| create draft | capture feature | local draft only after explicit owner choice |
| device preferences | settings | local by declared policy |
| account settings | account contract | synced and versioned |
| media | attachment service | local/remote completeness manifest |

Use one external store/database subscription rather than duplicating normalized data
inside several hooks. Every command returns a receipt containing record UID, local
revision, local durability, and remote queue state.
