# P4.4 Components and Touch Behavior

Captured: 2026-07-12 PDT

State: `EVIDENCE_READY`

Evidence ID: `EV-P4-CMP-004`.

## Component Findings

- 43/79 visible controls were under 44 px in at least one dimension; 19 lacked a
  detected programmatic name.
- Mobile navigation's center FAB is visually obvious but unnamed in the DOM.
- Settings sliders and toggles have nearby visual labels without reliable control
  names; several are 20-28 px high.
- Analysis help icons are 12x12 px targets.
- Filter chips are 28 px high and overflow without a visible affordance.
- Trade cards embed small edit affordances inside already dense card targets.
- The capture sheet combines modal dismissal, drag behavior, native date/time inputs,
  disclosures, sticky actions, autosave, and destructive edit in one component.

## Required Primitive Set

Build audited primitives for Button, IconButton, SegmentedControl, Field, MoneyField,
OutcomePicker, SliderField, SwitchField, Chip, SearchField, RecordCard, StatusReceipt,
Warning, BottomSheet, Dialog, Toast, Navigation, StickyActionBar, ChartFrame, and
Skeleton. Every primitive owns 44/48 px geometry, label/description/error links,
focus/pressed/disabled/loading states, safe-area behavior, and reduced motion.

Card surfaces should not be clickable containers with competing nested actions.
Journal record opens from one clear target; edit/delete/repeat live in an explicit
actions sheet. This reduces accidental destructive input and improves screen-reader
order.
