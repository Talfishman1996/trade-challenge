## Current Contract

| Layer | Contract |
|---|---|
| Client | hardcoded Worker origin and fixed `tradevault-main` key |
| API | unauthenticated GET/PUT by path key; POST creates arbitrary key; reflected Origin CORS |
| Payload | one full JSON dataset, shallow `trades[]` validation, 1 MiB Worker body cap |
| Storage | one Workers KV value; read-merge-write on every PUT |
| Consistency | wall-clock LWW by UID plus tombstones; dataset timestamp chooses initial equity |
| Acknowledgement | HTTP success only; no mutation/revision/object acknowledgement |

The contract cannot support the UI promise. KV is eventually consistent, permits one
write/second to the same key, and cannot make the Worker read-merge-write atomic.

## Target Free-Tier Contract

Use one SQLite-backed Durable Object as the serialized authority for the owner's
ledger. Cloudflare documents availability on Workers Free, 5 GB total free storage,
5 million rows read/day, and 100,000 rows written/day as of 2026-07-12. A Worker
performs authentication/validation and routes the account to the object.

```text
POST /v1/mutations
  request: mutationId, deviceId, baseRevision, command, payload, modelVersion
  response: acceptedRevision, affectedUIDs, serverTime, conflicts[]

GET /v1/changes?after=revision
  response: authoritativeRevision, ordered mutations/records, hasMore
```

Every mutation is idempotent by `mutationId`; revision is server-assigned and
monotonic. Records, tombstones, settings, model versions, and attachment manifests
are row-level objects rather than one rewritten blob. Authentication is a one-time
per-device session, not a user-entered sync key. Static assets can remain free on a
Worker while API routes invoke the Worker/Durable Object.
