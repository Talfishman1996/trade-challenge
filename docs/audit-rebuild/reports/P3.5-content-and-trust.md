## Trust Contract

Every message must answer one of four questions without implying more certainty:

1. What happened locally?
2. What has reached shared durable storage?
3. What did the model calculate, under which assumptions/version?
4. What should the user do next?

## Terminology Standard

| Concept | Required term |
|---|---|
| accepted in browser storage | Saved on this device |
| waiting for remote write | Waiting to sync |
| remote store acknowledgement | Uploaded |
| remote data applied locally | Merged from cloud |
| network unavailable | Offline; changes remain on this device |
| failed attempt | Sync failed; retry required |
| deterministic risk result | Next planned risk under Model vX |
| simulation result | Simulated probability under listed assumptions |
| zero realized result | Break-even, not Win or Loss |
| destructive grace period | Deleted; Undo available for N seconds |

## Tone and Decision Copy

- Prefer precise verbs over motivational certainty: calculated, saved, queued,
  uploaded, merged, simulated, estimated.
- Reserve green for verified positive/complete states, not merely absence of an
  exception.
- Never use a time estimate without horizon/frequency assumptions.
- Warnings must include threshold, observed value, consequence, and next action.
- Empty states should explain what data unlocks the view, not just ask for more
  trades.
- Help text must not be 10 px low-contrast copy when it contains assumptions or
  safety limits.
