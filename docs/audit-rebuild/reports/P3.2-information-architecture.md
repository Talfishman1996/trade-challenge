## Current Architecture

The application has five functional destinations but only four navigation states:

| Destination | Current responsibility |
|---|---|
| Home | account status, action, summary metrics, risk, equity curve, milestones |
| Trades | history, summary metrics, filter/sort/view, edit, delete, undo/redo |
| Analysis | Performance, Behavior, and Projections nested tabs |
| Settings | risk/simulation/display, sync, import/export, destructive data actions |
| Trade Entry | global create/edit overlay reachable from several destinations |

The center action is structurally outside the four destinations. That is reasonable
for a frequent capture task, but it has no programmatic name in the observed mobile
DOM and competes with additional Log/Log Trade actions inside Home and Trades.

## Ownership Overlap

Current surfaces repeatedly re-present the same objects:

- capture: Home headline, global FAB, Trades header, Trades empty state, Repeat Last
- performance: Home summary, Trades summary, Analysis Performance
- equity curve: Home modal and Analysis Performance
- progress: Home Summit Tracker and Analysis milestone roadmap
- model/risk: Home card and overlays, Analysis Projections, Settings controls
- manual sync: global floating control and Settings Cloud Sync

Repetition is not automatically wrong, but these copies do not have sharply distinct
questions. Home, Trades, and Analysis all partially answer “How am I doing?” while
no destination owns a concise “What changed after my last action?” handoff. This
opens `F-IA-HIGH-002`.

## Context and Navigation Tests

At 390x844 with mixed history:

| Test | Observed result |
|---|---|
| Change Home to Analysis | URL unchanged |
| Select Behavior, leave, return | resets to Performance |
| Select Projections, reload | returns to Home |
| Scroll Home to 602 px, leave, return | returns near top at 1 px |
| Browser Back after tab changes | no destination history exists |

`App` stores the primary destination in component state, conditionally renders only
one destination, and provides no router or state-restoration contract. Nested tab,
filter, view, and transient destination state unmount with the destination. This
opens `F-IA-HIGH-001`.

## Recommended Ownership Contract

- **Today/Home:** current equity, exact next risk, one primary capture action, last
  accepted record, durability state, immediate progress/drawdown consequence.
- **Journal:** complete record list, find/filter, edit/delete/recovery, weekly review
  entry points; summary metrics only when they help search or verify records.
- **Insights:** performance/behavior/model analysis with stable sub-routes and visible
  assumptions; no duplicate operational controls.
- **System:** settings, data lifecycle, sync detail, backup/import/export, diagnostic
  state; global shell shows only the minimum durability signal.
- **Capture:** locally committed sheet/flow preserving the invoking context and
  offering direct post-save edit/review.

Each destination should have a stable route/state key, retain relevant local context,
and define browser/hardware Back behavior. Reload must restore a safe equivalent of
the user's last durable location without restoring unsafe transient submission state.

## Limits

The tests establish current state loss and overlap. They do not yet decide final
labels, navigation count, or whether Insights should use tabs, drill-down routes, or
progressive disclosure. P4 and P10 own that design decision.
