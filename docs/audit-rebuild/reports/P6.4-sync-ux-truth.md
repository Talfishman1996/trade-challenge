## State Comparison

| UI state/copy | Evidence required | Current reality |
|---|---|---|
| Saved on this device | verified local transaction | storage exceptions swallowed |
| Syncing | one ordered operation with known mutations | overlapping PUT and pull/merge possible |
| Synced | all local mutations acknowledged at revision | global timestamp from any successful PUT |
| Merged | named remote revisions applied | whole dataset merge, no affected-record list |
| Offline | durable outbox retained | local data retained best-effort; no outbox records |
| Back online | reconnect convergence started | status flips Ready without `runSync` |
| Error | attempted operation failed and needs retry | returned `error` is routed to Ready unless thrown |

GET 404, GET 503, network failure, invalid JSON, and missing cloud data all collapse
to `null`. The store then interprets `null` as “No cloud data” and may attempt a PUT.
This opens `F-SYNC-HIGH-010`: transport failure and authoritative absence are not
distinguishable.

## Target UI State Machine

`local-writing -> saved-local -> queued -> uploading -> acknowledged(revision)`, with
parallel explicit states for `offline`, `retrying`, `conflict`, `blocked-auth`, and
`failed`. The global shell reports pending count and oldest age. Each record exposes
its revision/queue state. Settings shows last successful check, upload, download,
authoritative revision, device ID, pending operations, retry, and diagnostic export.

The transient pop-in remains appropriate for ordinary success; persistent actionable
UI is mandatory for pending > threshold, conflict, auth, storage, or transport error.
