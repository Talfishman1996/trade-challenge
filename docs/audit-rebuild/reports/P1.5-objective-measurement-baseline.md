# P1.5 Objective Measurement Baseline

Captured: 2026-07-12 PDT

## Measurement Environment

- Node 22.15.0, npm 10.9.2, Vite 7.3.1
- local macOS host, isolated Vite development server for runtime measurements
- browser-controlled Chromium-class environment, devicePixelRatio 1
- deterministic fixtures and production Worker interception
- requested viewport overrides from the P1 device matrix
- production asset build written outside `dist`

Local timing values are diagnostic, not field performance or physical-device proof.
Memory telemetry was unavailable. Accessibility results are bounded DOM/geometry and
contrast scans, not a substitute for P8 scanner/manual validation.

## Local Runtime Timing

At emulated M04, isolated development-load observations were:

| Fixture | FCP | LCP | CLS | Long tasks | Resources |
|---|---:|---:|---:|---:|---:|
| empty `$100K` | 148 ms | 148 ms | 0 | 0 | 34 |
| seven mixed trades | 144 ms | 144 ms | 0 | 0 | 34 |
| 500 trades on Home | 148 ms | 148 ms | 0 | 0 | 34 |

These values prove repeatable instrumentation and no gross Home scaling delta on a
fast local host. They do not prove acceptable mobile/Web Vitals performance. The
observed decoded development-resource total was 3.8-5.2 MB depending on cache state.

## Dataset Scaling

The 500-trade History grid produced:

- 8,185 live DOM elements
- a 39,961 px main scroll surface
- all 500 trade cards present simultaneously
- a 5,049-line accessibility snapshot
- no pagination, windowing, or virtualization
- approximately 399 ms from click through the fixed 100 ms settle interval in the
  browser-control measurement; this includes tool transport and is not a pure render
  duration

Home remains bounded because it summarizes the dataset. History cost scales directly
with every card. The exact stress behavior belongs to P8.2.

## Contrast Sampling

A CSS Color 4-aware scan composited visible leaf text against rendered ancestor
backgrounds and applied 4.5:1 normal / 3:1 large-text thresholds:

| Surface | Visible samples | Failing samples |
|---|---:|---:|
| Home | 22 | 8 |
| Analysis / Projections | 21 | 13 |
| Settings | 33 | 21 |

Worst Settings labels measured 2.27:1. Home failures cluster in 11-12 px secondary
labels; Projections failures include assumptions, reset action, and simulation copy.
Gradients, chart strokes, focus states, and disabled-state contrast are not covered
by this bounded baseline.

## Console and Network

Across the state corpus the browser recorded 29 warning/error entries:

- 27 warnings, dominated by Recharts mounting with width/height `-1` and duplicate
  React key `1` under the concurrent-device fixture
- two errors, including the daily-limit `fmt is not defined` crash

On the isolated development runtime:

- boot produced two GETs because React StrictMode replays effects in development;
  production is expected to run the boot effect once
- manual sync added one request
- one valid save added two requests, confirming the fire-and-forget PUT plus immediate
  pull/merge path

## Missing Measurements

- `performance.memory` was unavailable in the controlled browser.
- No physical iOS Safari or Android Chrome field timing exists.
- No genuine INP, virtual-keyboard, background-memory, battery, or thermal data exists.
- No production RUM exists, by prior scope decision.
- No third-party accessibility package was injected during the neutral baseline;
  P8 owns formal scanner and manual checks.

## Verification Result

Build/chunk/asset, local runtime, dataset scale, geometry/name, contrast, console,
and isolated request-count baselines are preserved under `EV-P1-MET-001` through
`EV-P1-MET-003`. Limitations are explicit and no result is represented as physical
mobile proof.
