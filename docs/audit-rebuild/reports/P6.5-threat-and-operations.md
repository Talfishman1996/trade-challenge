# P6.5 Informational Threat and Operations Review

Captured: 2026-07-12 PDT

State: `EVIDENCE_READY`

Evidence ID: `EV-P6-OPS-005`.

This is an informational architecture review, not a penetration test or compliance
certification.

## Highest Risks

| Risk | Current exposure | Control direction |
|---|---|---|
| unauthorized read/write | public known Worker/key, no auth, permissive reflected CORS | one-time device auth/session; deny-by-default origin/method; authorization tests |
| integrity loss | wall-clock LWW and non-atomic KV merge | serialized server revision and immutable mutation IDs |
| destructive client | any caller can PUT a valid-looking dataset | command validation, base revision, audit log, backup/restore |
| denial/quota exhaustion | no rate limit; full-blob requests; fixed shared key | authenticated per-device limits, bounded commands, backoff, metrics |
| privacy leakage | notes, psychology, P&L, and screenshots share one public boundary | least data, encrypted transport/at-rest provider, access revocation, attachment policy |
| silent operational failure | no alerting, request IDs, health/version, or backup drill | structured logs, metrics, deploy version, health diagnostics, restore exercises |
| release/data rollback mismatch | code versions do not roll back KV/D1/DO state | forward-compatible migrations and separate data rollback runbook |

## Operational Baseline

- Separate preview/production namespaces and credentials.
- Redacted structured logs with request/mutation/revision IDs, never full notes/P&L.
- Alerts for error rate, auth failure spike, queue age, storage/quota, migration, and
  backup failure.
- Daily logical backup plus periodic verified restore to an isolated namespace.
- Device/session list with revoke-all recovery.
- Compatibility-date and dependency update cadence.
- Incident runbook: freeze writes, export state, identify revision, restore/replay,
  verify invariants, communicate visible status.

SQLite-backed Durable Objects currently document encrypted data at rest/in transit
and point-in-time recovery capabilities, but provider controls do not replace app
authorization, validation, backups, or user-visible recovery.
