# P10.2 Workflow and State Specification

Captured: 2026-07-12 PDT

State: `EVIDENCE_READY`

Evidence ID: `EV-P10-FLOW-002`.

## Universal Interaction Contract

- Minimum interactive target: 48x48 CSS px; 44x44 is the absolute exception floor.
- No correctness-critical default for outcome, direction, or destructive action.
- Native input remains visible above the keyboard; the active field scrolls into a
  16 px comfort region and sticky actions never cover it.
- Validation occurs on blur and submit; the first invalid field receives focus.
- Local acceptance is transactional and returns a record ID/revision before the
  Capture surface closes. Remote sync never blocks that transition.
- Every mutation has `idle -> validating -> committing-local -> accepted-local ->
  queued|verified|failed-local` states. Remote state independently has `not-needed ->
  queued -> uploading -> acknowledged -> merged|conflict|failed` states.
- Buttons never change width while loading. Disabled states state why when ambiguity
  is possible.
- Money is signed and parsed losslessly in minor units. Display formatting never
  feeds calculations.

## W01 Open and Orient

1. Shell renders immediately from deterministic device state.
2. Today states strategy equity, next planned risk, and durability.
3. Empty state explains that `$100,000` is the configured strategy start and offers
   `Log first trade`.
4. Loading skeleton is structural, not a full-screen spinner.
5. Malformed state opens a recovery panel; it never shows a fabricated `$0` ledger.

Acceptance: primary values and action are reachable without scrolling at 320x568;
offline and pending states remain truthful.

## W02 Inspect Next Risk

1. Activate Next Risk card/details.
2. Show exact unrounded calculation internally and rounded display value, current
   strategy equity, percentage, anchor segment, `100k-pchip-v1`, gross 1:1 meaning,
   and validity warning for cross-margin liquidation behavior.
3. Under `$100K`, explicitly say 15% of current strategy equity.
4. At/above `$10M`, show challenge complete and no recommendation.

Acceptance: all anchor fixtures match canonical vectors; no amount is presented as
an exchange order or liquidation-safe position size.

## W03 Log Basic Trade

1. Open Capture from the named global action.
2. Choose exactly one of Win, Loss, Break-even. Nothing is preselected.
3. Enter realized net P&L manually. Outcome and sign must agree except Break-even,
   which permits a small cost-only negative value after explicit acknowledgement.
4. Instrument is required; direction may be `Long`, `Short`, or `Not recorded` but
   is never silently inherited.
5. Submit.
6. Device receipt appears immediately with record number/UID, consequence, and
   Waiting to sync or Verified state.

Acceptance: no positive default, no auto-filled profit/loss, one submission produces
one UID/revision, and double tap cannot duplicate it.

## W04 Log Detailed Trade

Expand optional execution detail: strategy, setup tags, opened/closed timestamps,
notional, entry, exit, order type, maker/taker mix, fees, slippage estimate, funding,
screenshots, and notes. Prototype attachments are simulated metadata only.

Acceptance: collapsing details never clears entered values; invalid numeric
combinations are explained without blocking unrelated optional fields.

## W05 Save and Add Another

After local acceptance choose `Log another`. Instrument/strategy may be offered as
explicit carry-forward chips, all off by default. Outcome, realized P&L, direction,
timestamps, prices, costs, and notes always reset.

Acceptance: the retained-field summary is visible before editing the next record.

## W06 Edit and Autosave

Record detail opens an Edit mode. Field changes create a local revision after a
650 ms quiet period or explicit Save. Leaving during commit waits only for the local
transaction. A receipt states revision and remote state.

Acceptance: remote conflict never silently overwrites either version; rapid edits
coalesce into one queued latest revision while preserving revision ancestry.

## W07 Delete and Recover

Delete requires a record-specific dialog. Confirmation creates a tombstone and an
8-second `Deleted trade <ID> - Undo` receipt. Undo targets only that tombstone.
After expiry, recovery remains available in System for the prototype scenario but
production hard-delete policy is deferred.

Acceptance: deleting A can never undo/delete B; deletion syncs as a tombstone and a
stale edit becomes conflict, not resurrection.

## W08 Find an Old Trade

Search indexes instrument, notes, strategy, tags, and display ID. Filters cover
outcome, direction, date range, strategy, sync state, and reviewed state. Sort is
newest/oldest/largest win/largest loss. Search is debounced visually but immediate
for keyboard submit.

Acceptance: 500-record fixture remains bounded, result count is announced, query
survives detail/Back/reload, and no-result state preserves filter controls.

## W09 Understand Drawdown

Today shows an actionable condition only when relevant. Insights Performance owns
peak equity, current equity, absolute/percentage drawdown, start date, trades since
peak, largest contributors, and next review link. It never says drawdown is safe.

Acceptance: realized ledger values drive drawdown; projections never replace them.

## W10 Understand Progress

Today owns current segment and next milestone. Insights Plan owns all milestones,
realized progress, planned risk curve, and simulation ranges. Achieved, active,
planned, and simulated use distinct semantics.

Acceptance: crossing and falling below a milestone is represented as previously
reached plus current position, not erased history or false current achievement.

## W11 Inspect Projections

Select 65/70/75% resolved-trade win rate and a horizon. Always show 10% BE, 3.5
trades/month, gross 1:1, cost profile state, path count/seed, model version, strategy
equity boundary, and cross-margin validity warning. Prototype displays frozen
published results rather than running a new Monte Carlo engine.

Acceptance: output is labeled simulation, never forecast or guarantee; unsupported
cost profile withholds deadline probability rather than substituting zero costs.

## W12 Manual Sync

System Sync has `Check now`. One activation transitions through Checking and reports
separate Last checked, Last uploaded, Last merged. No changes returns `Checked - no
changes`; failure reports reason and Retry. The shell receipt fades after 2-3 seconds.

Acceptance: check time never overwrites upload/merge time and the control remains
reachable after failure.

## W13 Offline and Reconnect

Offline Capture commits locally and queues the record. Reconnect starts serialized
sync immediately, with backoff only after failure. The record receipt moves through
Waiting -> Uploading -> Verified or Attention.

Acceptance: reconnect never changes Ready/Synced before acknowledgement; repeated
online events do not duplicate upload.

## W14 Import and Export

Prototype exposes a simulated export manifest and import preview, clearly marked.
Production contract requires schema/model versions, record/media/settings counts,
hashes, validation, deduplication, migration preview, transactional commit, and
rollback artifact.

Acceptance: prototype cannot imply it downloaded or restored real production data.

## W15 Change Settings

Every setting has label, current value, consequence, default, and reset. Risk
controls distinguish warning, acknowledgement, and block semantics. Prototype
settings persist in isolated local storage and never alter the canonical model.

Acceptance: changing display preferences has no model effect; invalid threshold
relationships are prevented and explained.

## W16 Background and Resume

On visibility return, rehydrate local state, inspect queued mutations, then check
remote if online. Display a receipt only for a material change or failure. Capture
input survives a benign suspend via hidden recovery transaction but is never listed
as a saved draft.

Acceptance: resume does not submit, discard, duplicate, or falsely verify a record.

## W17 Failure Recovery

Malformed fixture, local write failure, remote failure, conflict, timeout, storage
pressure, and component crash each have a bounded state. The shell remains navigable;
recovery offers retry, inspect details, export diagnostics, or reset fixture as
appropriate.

Acceptance: no failure state fabricates ledger/model values; daily-loss and tilt
controls render all thresholds without a whole-app crash.

## Review Cadence

- Immediate consequence: after every accepted trade.
- Review due: after four new resolved trades or 30 days with unreviewed activity,
  whichever occurs first.
- Exception review: surfaced after three consecutive losses, a newly crossed 20%
  drawdown band, a conflict, or a risk-control acknowledgement.
- The prototype records review completion locally; it sends no Telegram or analytics.

## Required Copy

- `Saved on this device`
- `Waiting to sync`
- `Uploaded`
- `Merged from cloud`
- `Offline - changes remain on this device`
- `Sync failed - retry required`
- `Next planned risk under 100k-pchip-v1`
- `Simulation under listed assumptions`
- `Deleted - Undo available for 8 seconds`
