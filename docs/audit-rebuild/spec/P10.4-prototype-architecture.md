# P10.4 Isolated Prototype Architecture

Captured: 2026-07-12 PDT

State: `EVIDENCE_READY`

Evidence ID: `EV-P10-ARCH-004`.

## Isolation Boundary

The prototype lives under `prototype/`, builds from `prototype.html`, uses
`vite.prototype.config.js`, and outputs `dist-prototype/`. It must not import
`src/store`, `src/sync.js`, the production Worker URL, production localStorage keys,
or production build/deploy commands.

Runtime guard requirements:

- fail startup if hostname equals the production origin without an explicit future
  production build mode that is outside this program;
- intercept adapter requests and reject any non-local/non-fixture URL;
- use storage namespace `tradevault:summit-prototype:v1` only;
- display `INTERACTIVE PROTOTYPE - SYNTHETIC DATA` in the review disclosure;
- include no secret, GitHub credential, Cloudflare token, or shared sync code.

## Module Boundaries

```text
prototype/
  app/          route state, composition root, error boundaries
  domain/       trade, equity, outcome, review, sync value types/reducers
  model/        100k-pchip-v1 pure implementation and frozen vectors
  adapters/     fixture ledger, isolated local persistence, simulated sync clock
  features/     today, capture, journal, insights, system, review-harness
  ui/           tokens, primitives, patterns, icon wrappers, chart helpers
  fixtures/     deterministic scenarios and manifest
  testing/      scenario assertions and browser hooks
```

Feature modules consume domain interfaces, never adapter internals. UI consumes
semantic view models, never calculates money, risk, drawdown, or sync authority.

## State Ownership

| State | Owner | Persistence |
|---|---|---|
| trades/revisions/tombstones | ledger adapter | isolated localStorage fixture transaction |
| strategy equity/drawdown/streak | pure selectors | derived from accepted records |
| planned risk | canonical model module | derived; never persisted as current truth |
| historical risk/R | execution snapshot on record | immutable |
| outbox/remote states | simulated sync adapter | isolated adapter state |
| route/query | route store | History API/URL |
| form transaction | Capture feature | memory plus hidden recovery key |
| display/risk-control preferences | System feature | isolated settings key |
| toast/sheet/dialog | app shell | ephemeral state machine |
| review harness scenario | fixture controller | URL and explicit reset |

## Ledger Contract

```text
create(input, mutationId) -> {record, localRevision, durability}
update(uid, baseRevision, patch, mutationId) -> accepted | conflict
delete(uid, baseRevision, mutationId) -> tombstone
restore(uid, tombstoneRevision, mutationId) -> restored | conflict
search(query) -> paged/virtualized records
subscribe(listener) -> unsubscribe
resetFixture(fixtureId, seed) -> fixture manifest
```

Mutation IDs are idempotent. UIDs are stable opaque IDs; display numbers are not
identity. Equal timestamps never select winners. Prototype conflict outcomes are
deterministic fixtures, not a claim that a production merge engine exists.

## Model Contract

The module exports `MODEL_ID`, immutable anchors, `plannedRisk(equityMinor)`,
`riskFraction(equityMinor)`, `segmentFor(equityMinor)`, and formatted explanation
view models. It uses Float64 calculation against dollars then converts to display;
ledger amounts remain integer minor units. Tests consume frozen P7 vectors.

## Routing and Chunks

Today and shell are initial. Journal, Insights, System, and review harness are lazy
route chunks with named error boundaries. Capture is prefetched after shell idle.
No Recharts or Framer Motion enters the prototype; charts are purpose-built SVG and
motion is CSS-token based.

## Error Boundaries

- app shell: protects navigation and recovery entry;
- route: isolates destination render failures;
- evidence plate/chart: replaces only that analysis;
- adapter: typed errors (`storage`, `malformed`, `conflict`, `network-simulated`);
- model: invalid/terminal result, never a thrown render exception.

## Fixture Manifest

Each scenario declares ID, schema version, seed, current clock, trades, tombstones,
outbox, remote state, settings, expected equity, expected planned risk, expected
visible conditions, and checksum. Reset is a single transaction and reload produces
the same visible state.

## Verification Hooks

Development-only `window.__SUMMIT_REVIEW__` may expose read-only scenario ID,
fixture checksum, ledger summary, route, and last mutation receipt. It cannot mutate
except through an explicit reset method available only on `/prototype/review`.
Production staging build preserves disclosure and fixture controls but no dev-only
global.
